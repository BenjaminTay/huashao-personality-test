# 人格分布优化：诊断基线、原则与路线图

> 状态：阶段 0、阶段 2（Question Set v3.1）与阶段 3（Archetype Coordinates v2.1）均已完成 2026-09-03；剩阶段 1 观测与阶段 4（视真实数据）。
> 创建日期：2026-09-03。所有涉及“不可随意修改项”的改动，需产品负责人批准并同步版本号。

## 1. 一句话结论

模型层面存在可测量的偏斜与“隐身”问题，但**优化目标是健康度，不是均匀分布**。优先做的是：消除孪生选项、给毛阿敏/陈意涵补主场、平衡维度覆盖、拉开三对紧邻人格；然后在真实样本达到阈值后，用埋点数据修正选项文案的社会称许性偏置。

## 2. 诊断基线（2026-09-03 实测，v3.0）

> 本节是 v3.0 时代的基线（诊断工具的快照已在 v3.1 合入时更换为 `BASELINE_V31`，见 §7 重跑命令与 v3.1 合入记录）。保留本文作为当初发现问题的证据与 v3.0→v3.1 的对照。

方法：对 24 题 × 4 选项做 50 万次完全随机作答（答案空间基线），叠加三类结构分析——选项“最近人格”归属、六维覆盖、七型自洽路径。所有数值基于当时 `Question Set v3.0 Final Candidate` 与 `Archetype Profiles v2.0`。

### 2.2 结构诊断

口径说明：以下“最近型 / 孪生 / 槽位 / 出场”均指**与最终分类器一致的题内校准贡献 argmax**（`getQuestionContribution` 最大者，即“选了这个选项最喂谁”），不是六维空间的纯几何最近距离。两者在有偏差校准的模型里不完全等价；草稿阶段的 12/24 孪生数是几何口径，正式工具已统一为贡献口径。

**A. 部分题目存在“孪生最近型”**：6/24 题有两个选项的贡献 argmax 指向同一个人格（Q04、Q05、Q07、Q16、Q20、Q24）。重复最多的是杨洋（Q16/Q20/Q24 各有一对双选项），宁静（Q04）、郑爽（Q05）、陈意涵（Q07）各一对。这类选项对同型用户仍有维度细差，但对“分型”是浪费，还会放大该型地盘。

**B. 中部人格曝光偏低**：96 个选项槽位中“唯一贡献 argmax”数量为 yang 20、zheng 19、jing 13、mao/xu/ning/chen 各 11；出场题数为 zheng 18、yang 17、jing 12、mao/xu/ning 11、**chen 10**（其余 12–18 题）。毛阿敏、许晴、宁静与陈意涵同处临界线，陈意涵最低。

**C. 六维覆盖不均衡**：R（关系占内存）10 题，B（边界感）与 G（收拾残局欲）各 7 题。48 个维度槽位远离 8±1 的理想区间，等于暗中给“靠 R 取胜”的人格（许晴、郑爽）加权。

**D. 三对紧邻人格，自洽领先分差小**：

| 人格对 | 坐标距离 |
| --- | --- |
| 毛阿敏 ↔ 井柏然 | 2.07 |
| 宁静 ↔ 陈意涵 | 2.33 |
| 陈意涵 ↔ 杨洋 | 2.51 |

自洽路径（每型全程选最贴近自己的选项）回到自身的领先分差：xu 14.6、zheng 14.8、ning 11.8、yang 10.3 都较稳；**mao 4.5、jing 4.9、chen 5.2** 很浅——边缘用户会在这三型之间漂移。

## 3. 优化原则（先对齐，再动手）

1. **不做平均化**。随机基线 2.36× 不构成问题；把它压平会牺牲选项真实感，且对真实人群无意义。
2. **真正的健康标准**：
   - 每个型有自己的稳定主区（贴近某型 → 稳定测出该型）；
   - 没有型“隐身”（陈意涵现状属于隐身）；
   - 每题选项尽量向不同方向分叉（孪生选项是浪费）；
   - 维度负担均衡（避免某个维度暗中决定结果）。
3. **真实数据优先于几何直觉**。选项文案的“顺口/体面程度”对真实分布的影响大于坐标几何；改版节奏要等真实样本说话。
4. **遵守冻结项**。题目 ID、题目顺序、四幕、六维语义、人格 ID、主型分类器（Calibrated Item-Profile Matching v3.0）不动。可演进的是：24×4 评分矩阵数值、选项正文文案、人格坐标——都需新版本号 + 全套同步。
5. **一切改动可回归、可对照**。先有诊断工具与基线快照，才有资格谈优化。

## 4. 建议验收指标（健康门槛，非均匀指标）

| 编号 | 指标 | 当前 | 目标 |
| --- | --- | --- | --- |
| G1 | 七型自洽路径回到自身 | 7/7 | 保持 7/7（回归门槛） |
| G2 | 每题最近型分叉 ≥ 3 个不同人格 | 孪生题 6/24 | 孪生题 ≤ 4/24 |
| G3 | 每型出场题数（有选项的贡献 argmax 是它） | mao/xu/ning 11、chen 10 | ≥ 12（v2.1 后全达） |
| G4 | 每型“唯一贡献 argmax”槽位 | mao/xu/ning/chen 11 | ≥ 12（v2.1 后全达，chen 13） |
| G5 | 六维维度槽位 | R10 / B7 / G7 | 6–9 题/维（需正文级改版，见提案 §6.3） |
| G6 | 自洽路径领先分差 | mao 4.5 / chen 5.2 / jing 4.9 | mao/xu/ning/zheng/jing/yang ≥ 8；chen ≥ 7.5（v2.1 达标：chen 7.82）¹ |
| G7 | 随机基线最高/最低（参考，不硬性） | 2.36× | 改版后记录，目标 ≤ 2.0× |

> ¹ chen 例外历史：v3.1 曾按 ≥10 验收 chen 的槽位/出场（其主场文本稀缺），坐标 v2.1 拉开后 chen 已达 13/13，G3/G4 例外解除；G6 对 chen 保留 ≥7.5（语义档位约束内的局部上界 7.82，见 [ArchetypeCoordinates-v2.1-提案.md](ArchetypeCoordinates-v2.1-提案.md) D5b）。

真实人群口径另行观察：≥ 50 人次可显示百分比，≥ 200 人次才做分布结论。

## 5. 路线图

### 阶段 0：工具化 —— ✅ 已完成（2026-09-03）

产物（全部只读新增，未改动 data/ 与 lib/scoring.ts）：

- `lib/model-diagnostics.ts`：指标函数与基线快照 `BASELINE_V31`（随机基线 MC、孪生/分叉检测、唯一槽位、出场题数、维度覆盖、自洽路径与领先分差、最近邻距离）；
- `lib/model-diagnostics.test.ts`：数据完整性 + G1 自洽硬门槛 + 快照一致性 + MC 确定性，随 `npm test` 回归；报告仅在诊断模式下打印；
- `npm run diagnose`（打印体检报告与缺口清单）与 `npm run diagnose:strict`（G2–G6 目标门槛失败即退出非零，作发布门禁）。

口径修正记录：指标统一采用与分类器一致的贡献 argmax 口径（见 §2.2）。快照断言会把意外的模型漂移拦在测试里；有意的改版需要人工更新基线快照后再放行。

### 阶段 1：观测期（真实样本积累）

- 保持当前版本上线，GoatCounter 埋点继续积累；
- 里程碑：≥ 50 人次看首份“测友坐标”走向；≥ 200 人次做首次真实分布分析，与 2.1 随机基线对照，判断文案偏置方向；
- 输出：《真实分布首报》，决定阶段 2/3 的优先级。

产品待决策（不默认执行）：是否给“再测一次”打标，以测量主型稳定性（同一用户两次是否同型）。这需要新增埋点字段/事件，属于埋点决策，要更新 `lib/analytics.ts` 与《结果系统产品体验与隐私决策》后再做。

### 阶段 2：评分矩阵演进（Question Set v3.1）—— ✅ 已完成（2026-09-03）

只动 `data/question-scoring.v3.ts` 的矩阵数值与版本号；题目 ID、顺序、正文、选项文本与四幕一律不动。合入记录与评审取舍见 [QuestionSet-v3.1-评分矩阵提案.md](QuestionSet-v3.1-评分矩阵提案.md)。

验收：跑诊断，G1 保持、G2/G3/G4/G5 达门槛；`lib/scoring.test.ts`、版本变量、docs/decisions 的题库演进文档、README 基线表同步；人工抽查改后选项文本与矩阵语义是否仍一致。

注意：矩阵一变，六维展示分、证据链、主型输出都会变，必须全套回归；此改动同时影响“不可随意修改项”中的 v3 矩阵与展示分结果，需负责人明确批准后执行。

### 阶段 3：人格坐标拉开（Archetype Coordinates v2.1）—— ✅ 已完成（2026-09-03）

在语义档案档位约束内做自动搜索后合入：chen 低 R/G 更极端、yang 低端拉满、mao D/G 下压、ning D 到 5.0；jing 不动。效果：chen 槽位 10→13、弱三型自洽 margin 5.5→9.0+（chen 7.8，按 D5b 验收）、yang↔chen 距离 3.13。依据与取舍见 [ArchetypeCoordinates-v2.1-提案.md](ArchetypeCoordinates-v2.1-提案.md)。

### 阶段 4：文案偏置修正（基于真实数据，需批准）

当阶段 1 的真实分布显示某型因“选项太顺口/太体面”被过度选择时，只改对应题目的选项正文（不改 ID、顺序、维度归属），并更新 Question Set 版本号与题库文档。改法原则：让选项更像“真实的自己”的取舍，而不是“听起来更好的人”。

### 持续

- 每次题库/矩阵/坐标改版，先跑 `npm run diagnose` 出“体检报告”，再决定放行；
- 数据完整性 + G1 自洽门槛随 `npm test` 常绿；`npm run diagnose:strict` 作为发布门禁（G2–G6）。

## 7. 附录：重跑诊断

```bash
npm run diagnose          # 打印体检报告（全部指标 + 基线对照 + 缺口清单）
npm run diagnose:strict   # 同上，且 G2–G6 未达标时退出非零（发布门禁）
npm test                  # 数据完整性 + G1 自洽 + 基线快照常绿
```

本文第 2 节数字即当前版本的基线快照，报告应输出“当前 vs 基线”差异，避免版本演进后基线丢失。

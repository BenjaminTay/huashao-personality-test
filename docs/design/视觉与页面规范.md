# 花学测试｜视觉与页面规范

## North Star

不是做一个普通心理测试网站，而是做一份被互联网考古出来的“花学人格档案”：前半程像漂亮、轻松的生活问卷，中段逐渐进入关系修罗场，最后像真人秀节目组给用户出了一份带互联网损友语气的人格鉴定报告。

视觉方向：

> 2015 旅行手账 × 节目场记 × 花学研究所 × 互联网考古档案

必须是原创档案语言，不复刻《花少 2》官方海报、Logo、节目截图或明星肖像。

## 视觉关键词

旅行手账、米白纸张、旧杂志、路线图、护照章、行李牌、录像时间码、红色手写批注、扫描边缘、档案编号、轻微故障、研究记录、未完成的关系图。

## 色彩与材质

建议使用 CSS 变量，组件不要散落硬编码颜色：

```css
:root {
  --paper: #f3efe6;
  --paper-deep: #e5ddce;
  --ink: #1d211d;
  --muted-ink: #6f7069;
  --archive-red: #b64c3e;
  --travel-blue: #4c7180;
  --signal-green: #778c68;
  --line: rgba(29, 33, 29, 0.18);
  --shadow: rgba(29, 33, 29, 0.12);
}
```

- 背景以暖白、米白、纸张深浅层次为主；
- 正文使用深墨色，红色只用于批注/警示/记录点；
- 蓝色或绿色作为少量旅行与系统状态强调；
- 纸张纹理应轻，不得影响正文对比度；
- 阴影像纸片叠放，不使用厚重的 SaaS 卡片渐变；
- 破折线、虚线、印章、时间码可以增强档案感，但不能让页面变得嘈杂。

## 字体

优先使用项目内打包、具备可靠中文覆盖的字体；没有本地字体时才回退到系统字体栈：

```css
--font-display: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;
--font-body: "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace;
```

大标题可以使用衬线体建立档案/杂志感，题目和按钮使用清晰无衬线体，编号、REC、状态和评分使用等宽字体。不要为了“复古”牺牲中文可读性。

## 信息层级

每个页面最多保留一个主要动作。整体由三层组成：

1. **档案层**：`花学测试 / FLOWER STUDIES`、`CASE #002`、章节、REC、日期/时间码；
2. **内容层**：题目、选项、结果文案、六维分数；
3. **批注层**：红色手写感短句、系统状态、心眼子彩蛋、证据标签。

## 页面结构

### 1. 首页

第一屏要让用户一眼理解并愿意开始：

```text
花学测试 / FLOWER STUDIES
CASE #002

花 学 测 试
你到底是《花少2》里的谁？

看看你在旅行团里通常是什么位置。

[ 开始鉴定 ]
```

可以随机轮换一条副标题，例如“看看你的‘我都可以’到底有几分可信度”。首页不要提前展示七个人的完整图鉴，避免用户按目标人格作答。

### 2. 答题页

坚持一屏一题：

- 顶部显示档案标题、当前幕、`08 / 24`、进度条和 `REC` 状态；
- 中部显示题目标题、生活化情境正文；
- 下方显示四个完整选项，选项有明显编号和触摸反馈；
- 顶部提供“返回首页”，离开答题页时保留当前进度；
- 底部提供“上一题”，第一题隐藏或禁用；
- 选择后高亮/轻微缩放，约 200–300ms 自动前进；
- 返回修改后要恢复该题原选项，不丢失后续答案；
- 不在选项旁解释它代表哪种人格，不显示内部维度和评分。

章节状态文案可以随幕变化：

- Act 1：`所有人目前都很礼貌` / `关系状态：风平浪静`；
- Act 2：`有人开始说没事` / `关系状态：空气开始微妙`；
- Act 3：`大家开始要你表态` / `关系状态：关系变得复杂`；
- Act 4：`旅程结束以后` / `关系状态：旅程结束以后`。

### 3. 四幕过场

Q1–Q6、Q7–Q12、Q13–Q18、Q19–Q24 分成四幕。过场应是短暂的全屏章节卡，不阻塞用户太久：

```text
第二幕
气氛开始变微妙

“没事”
“随便”
“你想多了”

出现频率 ↑ 247%
[继续观察]
```

Act 3 可以增加故障、批注和更密集的 REC；Act 4 重新安静下来，突出“真正看出人格的是第二天”。

### 4. 鉴定 Loading / Reveal

Q24 后给用户一个约 5–8 秒的戏剧性体验，但必须允许跳过或在减少动效时立即完成。文案逐条切换：

- 正在读取你的关系占内存……
- 正在核算“我都可以”可信度……
- 正在清点你的心眼子余额……
- 正在检查你是否长期兼职公共情绪客服……
- 正在确认：你是读局的人、修局的人、退局的人，还是根本没发现这里有个局……

不要显示原始分数、算法步骤或“正在匹配某某明星”。

### 5. 结果页

结果页按以下顺序组织：

1. 主人格揭晓；
2. 一句话暴击；
3. 六维面板；
4. 为什么是你（3 条真实答题证据）；
5. 高光面；
6. 花少 BUG / 影子面；
7. 副型与第二名的区别；
8. 最不像谁；
9. 心眼子彩蛋、档案台词和分享卡。

六维不要只放一个雷达图。建议采用条形/刻度面板加短状态句，雷达图只能作为辅助。显示 0–100 的展示分，并明确它是本次答题画像，不是概率或科学测量分数。

### 6. 分享卡

分享卡是传播核心，至少准备：

- 3:4 竖版：适合相册、小红书、微博；
- 9:16 竖版：适合朋友圈/Story；

卡面内容控制在：

```text
花 学 测 试
YANG YANG TYPE
真的来旅游的人

心眼子余额：拉完了
别人已经宫斗第三轮，
你还在确认今天几点出发。

[六维迷你图]   [二维码/链接]
扫码测测你是谁
```

不要把完整结果文章塞进卡片。二维码和链接应指向公开测试入口；如果实现分享参数，只使用匿名短 ref，不携带原始答案。

## 动效规范

- 页面进入：纸片/档案页轻微错位后归位，约 350–500ms；
- 选择反馈：背景、边框、编号颜色和轻微缩放，约 180–240ms；
- 自动前进：选择反馈结束后再切换，避免点击后瞬移；
- 章节切换：短暂擦除/扫描线/印章感，约 400–700ms；
- 结果揭晓：标题、称号、暴击句分层出现，控制在 1–2 秒；
- Loading：文案渐变/打字感可以有，但必须可跳过；
- `prefers-reduced-motion: reduce` 时取消位移、故障和延迟，直接显示状态。

禁止：持续闪烁、过度噪声、依赖声音才能理解、超过数秒的无意义等待、自动播放带声音的媒体。

## 移动端与可访问性

- 以 390px 宽度验收，额外检查 320px 和桌面宽度；
- 页面不得横向溢出，长题干要自然换行；
- 选项/按钮最小触摸区域约 44px，高对比度，焦点可见；
- 颜色不是唯一信息来源，REC、选中、警示都要有文字/图形辅助；
- 进度条有可读文本和 `aria-valuenow`；
- 过场和 Loading 使用适当的 live region，但不要让屏幕阅读器反复播报整页；
- 结果图表要有文本替代；
- 交互不依赖 hover，键盘可完成答题和返回；
- 安全区适配 iPhone 底部，避免固定按钮挡住选项；
- 图片、纹理和字体要压缩，首屏不因装饰素材明显变慢。
